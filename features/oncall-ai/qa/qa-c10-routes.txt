BUG-009 (MED) — GET /incidents/:id `pull_request` DTO omits SPEC §7.3 fields
================================================================================
SPEC §7.3 (source of truth, lines 319-321) defines the pull_request DTO as:
  { "number","url","kind","state","verification_status","branch","base","head_sha" }
Impl returns only 5 of the 8 fields — branch, base, head_sha are dropped:
  packages/shared/src/github.ts  PullRequestSummarySchema  → {number,url,kind,state,verification_status}
  packages/server/src/incidents/detail.ts:40 toPullRequestSummary → same 5 fields
The underlying pull_requests row (§8) HAS branch, base_branch, head_sha — they are
simply not projected onto the wire DTO.

Traceability: SPEC §7.3 was AMENDED to add branch/base/head_sha as the resolution of
BUG-003 (C11 DESIGN QA, VERIFIED) specifically so the dashboard PRCard (DESIGN_SPEC §8.6/§13)
could bind them. C10 shipped the DTO WITHOUT them, reopening that gap at the API layer.
Downstream impact: C13 PRCard cannot render branch/base/head_sha from the documented
contract (@oncall/shared consumers get a 5-field object).

Executed proof (qa-c10-routes.test.ts TC-24): with a fully-populated PR row
(branch 'oncall-ai/fix-inc_x-a1b2c3', base 'main', head_sha 'def5678abcd'),
GET /incidents/:id → pull_request is { number,url,kind,state,verification_status } —
`expect(pr).toHaveProperty('branch')` FAILS. See suite output above.

Fix: add branch, base, head_sha to PullRequestSummarySchema (map base_branch→base) and
project them in toPullRequestSummary. Contract change stays within SPEC §7.3.
